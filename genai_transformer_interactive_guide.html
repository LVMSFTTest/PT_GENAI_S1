Key insight
The Transformer replaced RNNs by processing all tokens in parallel using attention. Each token computes how much to "attend" to every other token — this is what lets the model understand context far away in a sentence.

Encoder vs Decoder — what's the difference?

Think of it like reading vs writing. The encoder reads and understands; the decoder writes the output token by token.
Encoder — "understander"
Processes the entire input at once. Each token attends to every other token (bidirectional). Produces a rich context representation.
Example models

Classification, NER, Q&A (extractive), sentence similarity

Decoder — "writer"
Generates output one token at a time. Each new token can only see what came before it (autoregressive). This is how GPT works.

Encoder-Decoder — "translator"
Has both halves. Encoder reads the source (e.g. English). Decoder generates the target (e.g. French), attending to the encoder's output via cross-attention.

What are Q, K, V?
Query (Q)
"What am I looking for?"
This token's question
Key (K)
"What do I contain?"
Each token's identifier
Value (V)
"What info do I give?"
Actual content passed
Score = softmax( Q·Kᵀ / √d_k ) × V  — The dot product of Q and K measures relevance. Dividing by √d_k prevents gradients vanishing. Softmax normalises to probabilities. Then we take a weighted sum of V.
Why "multi-head"?
Head 1
Attends to grammar relations (subject ↔ verb)
Head 2
Attends to co-reference ("it" → "cat")
Head 3…N
Other learned relationships
All heads run in parallel on lower-dimensional projections, then their outputs are concatenated and projected back. This lets the model attend to different aspects of context simultaneously.

Masked (Causal) Attention

Used in decoder-only models like GPT. A token can only attend to itself and previous tokens — never future ones. This is how the model generates text left-to-right without "cheating".
Attention matrix — sentence: "the cat sat on"
Each row = a token's query. Coloured = allowed to attend. Grey dashed = masked out (future).
Row "sat" can attend to "the", "cat", "sat" — but NOT "on" (future). This masking is implemented by adding -∞ to future positions before the softmax, making them zero after the softmax.
Self-attention (Encoder)
All tokens ↔ all tokens. Full square matrix. Good for understanding — "sat" can use context from "on" to understand meaning.
Masked self-attention (Decoder)
Lower triangle only. Each token only sees its past. Enables autoregressive generation — predicting next word without seeing it.

Formula: FFN(x) = W₂ · ReLU(W₁ · x + b₁) + b₂

The hidden layer is typically 4× wider than the model dimension. This is where the model memorises facts and patterns learned during training. Think of it as a lookup table: attention finds where to look, FFN retrieves what is there.
Full layer data flow (one encoder layer)
1
Token embeddings arrive (shape: [seq_len × d_model])
2
Multi-Head Attention — each token gathers context from other tokens
3
Add & LayerNorm — residual connection added, then normalise (prevents vanishing gradients)
4
FFN hidden layers — W₁ expands to 3072-dim, ReLU activates, W₂ projects back to 768-dim
5
Add & LayerNorm — second residual + normalise. Output passed to next layer.
Why do we need the FFN at all?
Attention is a linear operation (weighted sums). On its own it can't learn non-linear patterns. The FFN introduces non-linearity (ReLU/GELU). Without FFN layers, stacking attention blocks can't learn complex functions like syntax rules or world facts.

Pre-training objectives
E
Masked Language Modelling (MLM) — BERT masks 15% of tokens and predicts them. Learns bidirectional context.
D
Causal Language Modelling (CLM) — GPT predicts the next token. Trains left-to-right generation.
ED
Span corruption — T5 masks random spans; the decoder must reconstruct them. Best of both worlds.
Fine-tuning approaches
1
Full fine-tuning — update all weights on task-specific data. Expensive but powerful.
2
LoRA / PEFT — freeze most weights, add small trainable matrices. 100× fewer parameters.
3
Prompt tuning — only train soft prompt embeddings. Even lighter.
4
RLHF — fine-tune with human preference feedback. Used for chat models.
